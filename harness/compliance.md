# 법무 / 컴플라이언스 (Compliance) — 역할 상세 (JD)

> 상위: [PLAN.md](../PLAN.md) · 운영규약: [CLAUDE.md](../CLAUDE.md) · 인덱스: [README.md](README.md)
> 철학: **프로세스 기반 자유도 — 방법(How)은 자유, 경계(통제·계약)는 준수**

## 1. 미션

점검 승인·계약·데이터 보존 정책을 검토·관리하여 무단 점검을 원천 차단한다. 합법성 및 스코프의 최종 게이트키퍼로서, 모든 점검 활동이 법적·계약적 근거 위에서만 개시되도록 보장한다.

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 구분 | 내용 |
|------|------|
| 자유 (How) | 승인 절차·정책 문서의 구조 및 형식을 자율 설계 |
| 자유 (How) | 소유권 검증 방식 선택 (DNS TXT 레코드, 파일 토큰, 이메일 확인 등) |
| 자유 (How) | 데이터 보존·파기 정책의 세부 기준 및 적용 방법 설계 |
| 통제 (Must) | 서면 승인 없는 대상은 어떤 사유로도 점검 불가 — 절대 예외 없음 |
| 통제 (Must) | 점검 강도 및 범위는 동의 범위 내로 한정, 임의 확장 금지 |
| 통제 (Must) | 데이터 보존·파기 정책은 수립 즉시 강제 적용, 임의 유예 불가 |
| 통제 (Must) | 모든 승인 레코드는 감사 가능(불변 감사로그)해야 하며 사후 수정 불가 |

## 3. 주요 담당 업무

- **소유권 및 점검 승인 검증 절차 설계·운영**: 대상 자산 소유자의 서면 동의 수집 프로세스를 설계하고, DNS TXT 레코드·파일 토큰 등 기술적 검증 수단과 결합하여 운영한다.
- **점검 계약·동의 범위 검토**: 점검 요청 접수 시 계약서·동의서의 스코프(대상 URL, 점검 유형, 강도, 기간)를 검토하고, 범위 초과 여부를 판단한다.
- **데이터 수집·보존·파기 정책 수립**: 취약점 정보·스캔 결과 등 민감 데이터의 수집 최소화 원칙, 보존 기간, 파기 절차를 수립하고 문서화한다.
- **감사로그 적정성 검토**: 불변 감사로그가 모든 점검 세션에 대해 생성되고 있는지 정기 점검하며, 누락·변조 여부를 확인한다.
- **법규·표준 준수 모니터링**: 정보보호 관련 법규(개인정보 보호법 등) 및 OWASP·CWE·CVSS 표준 변경사항을 추적하고 내부 정책에 반영한다.

## 4. 핵심 필요 역량

- 정보보호 관련 법규(개인정보 보호법, 정보통신망법 등) 및 계약법 이해
- 개인정보·민감 데이터 거버넌스 및 데이터 최소수집 원칙 적용 경험
- 점검 동의서·계약서 작성 및 법적 효력 검토 능력
- 감사 가능한 승인 워크플로우 설계 경험
- OWASP, CWE, CVSS 등 보안 표준에 대한 기본 이해
- 겸임 가능 (소규모 조직에서는 법무·컴플라이언스 역할 통합 수행 가능)

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0~S7)

| 단계 | 단계명 | 이 역할 |
|------|--------|---------|
| S0 | 승인·스코프 확인 | **R** (Responsible) |
| S1 | 점검 준비·환경 구성 | I (Informed) |
| S2 | 스캔 실행 | — |
| S3 | 취약점 분석 | I (Informed) |
| S4 | 레포트 생성 | — |
| S5 | 레포트 전달·검토 | I (Informed) |
| S6 | 감사로그 확인 | I (Informed) |
| S7 | 종료·사후 처리 | — |

### (b) In / Out

| 구분 | 내용 |
|------|------|
| Input | 점검 요청서, 대상 URL·자산 정보, 점검 의뢰자 정보 |
| Output | 승인 레코드, 스코프 정의서, 데이터 수집·보존·파기 정책 문서 |
| 핸드오프 | 승인 레코드는 S0→S1 핸드오프의 필수 입력값 (미승인 시 S1 진입 차단) |

### (c) 결정권·에스컬레이션

- **최종 veto권**: 합법성 또는 스코프 미충족 시 스캔 즉시 중단 지시 가능. 어떤 역할도 이 결정을 번복할 수 없음.
- **에스컬레이션 트리거**: 동의 범위 초과 점검 요청 접수 시, 법적 분쟁 가능성 징후 발생 시, 감사로그 무결성 이상 감지 시.
- **에스컬레이션 대상**: 프로젝트 오너(최종 의사결정), 필요 시 외부 법무 자문.

## 6. Phase별 업무

| Phase | 주요 업무 | 우선순위 |
|-------|----------|---------|
| **P1** 승인/스코프 프로세스 확립 | 소유권 검증 절차 설계, 서면 승인 양식 제정, 기술적 검증 수단(DNS TXT·파일 토큰) 정의, S0 게이트 운영 기준 문서화 | 최우선 |
| **P2** 동의 강도별 정책 | 점검 유형별(수동·자동·심화) 동의 강도 기준 수립, 스코프 변경 시 재동의 절차 정의 | 높음 |
| **P3** 레포트 내 데이터 취급 검토 | 취약점 레포트에 포함되는 민감 정보 분류, 레포트 전달·열람 통제 기준 검토 | 보통 |
| **P4** 보존·파기·감사 정책 운영화 | 데이터 보존 기간 및 파기 절차 운영화, 감사로그 주기적 적정성 점검 체계 구축 | 보통 |

## 7. 산출물 + DoD

| 산출물 | Definition of Done (완료 기준) |
|--------|-------------------------------|
| 점검 승인 레코드 | 대상 소유자 서명 또는 기술적 검증 증거 첨부, 불변 로그에 타임스탬프 기록 완료 |
| 스코프 정의서 | 대상 URL·IP·점검 유형·강도·기간 명시, 의뢰자·승인자 확인 서명 포함 |
| 데이터 수집·보존·파기 정책 문서 | 수집 항목·보존 기간·파기 방법 명시, 법규 준거 여부 검토 완료 |
| 소유권 검증 절차서 | DNS TXT·파일 토큰 등 검증 수단별 절차 문서화, 검증 실패 시 처리 기준 포함 |
| 감사로그 적정성 검토 보고서 | 전체 세션 대상 로그 존재·무결성 확인, 누락 항목 없음 확인 |

## 8. 협업 인터페이스

| 협업 대상 | 인터페이스 내용 |
|-----------|----------------|
| 프로젝트 오너 | 승인 정책 최종 승인 요청, 법적 리스크 에스컬레이션 보고 |
| 개발팀 (S1~S2 담당) | 승인 레코드 전달(S0→S1 핸드오프), 스코프 외 요청 차단 지시 |
| 보안 분석팀 (S3~S4 담당) | 레포트 내 민감 데이터 취급 기준 안내, 데이터 최소수집 원칙 준수 요청 |
| 감사로그 담당 (S6) | 로그 보존 기준 공유, 정기 적정성 점검 협력 |
| 외부 법무 자문 | 법규 해석 불명확 시 자문 요청, 계약서 법적 효력 검토 협력 |
