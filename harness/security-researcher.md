# 취약점 연구원 / Pentester (Security Researcher) — 역할 상세 (JD)

> 상위: [PLAN.md](../PLAN.md) · 운영규약: [CLAUDE.md](../CLAUDE.md) · 인덱스: [README.md](README.md)
> 철학: **프로세스 기반 자유도 — 방법(How)은 자유, 경계(통제·계약)는 준수**

## 1. 미션

OWASP Top10 탐지 로직을 정의하고, 후보 결함을 재현·검증해 오탐을 제거하며, 조치 가이드를 기술 검수한다. SecurityGuardrails 파이프라인에서 **"진짜 취약한가"의 최종 판정자** 역할을 수행하며, 방어적 목적의 증거 기반 취약점 확정을 책임진다.

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 구분 | 내용 |
|------|------|
| **자유 (How — 최대 자율)** | 탐지 기법·페이로드 설계 방식 선택 |
| **자유 (How — 최대 자율)** | 검증 방법·절차·순서 결정 |
| **자유 (How — 최대 자율)** | 사용 도구·스크립트·익스플로잇 프레임워크 선택 |
| **통제 (경계 — 반드시 준수)** | 비파괴 기본값 유지 및 승인 강도 준수; 스코프 밖 자산 테스트 금지; 무기화 익스플로잇 산출 금지(방어용 재현 PoC만 허용); 모든 취약점 확정은 재현 증거 필수 |

## 3. 주요 담당 업무

1. **탐지 로직·시그니처/페이로드 설계** — OWASP WSTG 기준으로 각 취약점 유형별 탐지 규칙, 시그니처, 페이로드 셋을 설계·문서화한다.
2. **능동 점검 수행** — 승인된 스코프 내 대상에 대해 능동 취약점 점검을 수행하고 후보 결함 목록을 생성한다.
3. **오탐 검증·증거 캡처·중복 병합** — 후보 결함을 취약 테스트 앱 또는 재현 환경에서 직접 재현하고, HTTP 요청·응답 증거를 캡처하며, 중복 결함을 병합한다. 오탐 논쟁은 토론이 아니라 재현으로 끝낸다.
4. **CVSS 산정** — 확정된 취약점에 대해 CVSS 점수(Base Score 이상)를 산정하고 근거를 기록한다.
5. **조치 가이드 기술 검수** — 리포트 엔지니어가 작성한 취약점별 조치 가이드의 기술적 정확성을 검수하고 피드백을 제공한다.

## 4. 핵심 필요 역량

- **OWASP WSTG 실무** — WSTG 전 항목에 대한 실무 수행 경험 및 적용 능력
- **웹 익스플로잇·취약점 분석** — SQLi, XSS, SSRF, XXE, IDOR, 인증 우회 등 OWASP Top10 전 범주 분석·재현 능력
- **증거 기반 검증** — HTTP 트래픽 캡처, PoC 재현, 오탐/진양성 판별 능력
- **CVSS 산정** — CVSS v3.1 이상 기준 정확한 점수 산정 및 벡터 문자열 작성 능력
- **방어적 시각** — 무기화가 아닌 방어·조치 관점에서 취약점을 서술하는 능력

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0~S7)

| 절차 | 설명 | 취약점 연구원 |
|------|------|:---:|
| **S0** | 승인·스코프 확정 | I |
| **S1** | 정보수집 | C |
| **S2** | 수동 점검 | R |
| **S3** | 능동 점검 | R |
| **S4** | 검증·오탐 제거 | A / R |
| **S5** | 위험도 평가 (CVSS) | R |
| **S6** | 레포트·조치 가이드 | C |
| **S7** | 재검증 | R |

> RACI 범례: **R** = Responsible(실행) · **A** = Accountable(최종책임) · **C** = Consulted(검토의견) · **I** = Informed(결과수신) · **–** = 미관여

### (b) Input / Output

| 방향 | 내용 | 출처/목적지 |
|------|------|-------------|
| **Input** | 자산 인벤토리 (승인된 URL·엔드포인트 목록) | 백엔드 / 인프라 엔지니어 |
| **Output** | 확정 취약점 + 재현 증거(요청·응답) + CVSS 점수 | 리포트 엔지니어 |

### (c) 결정권·에스컬레이션

| 항목 | 내용 |
|------|------|
| **단독 결정권** | 오탐 여부 최종 판정 — 취약 테스트 앱 재현 데모로 판정하며 번복은 새 재현 증거로만 가능 |
| **에스컬레이션 기준** | 스코프 외 자산 발견 시 즉시 중단 후 프로젝트 오너에게 보고; DoS 위험이 있는 페이로드 필요 시 사전 승인 요청 |
| **에스컬레이션 경로** | 취약점 연구원 → 프로젝트 오너 → 자산 소유자(승인자) |

## 6. Phase별 업무

| Phase | 주요 업무 |
|-------|-----------|
| **P1** | Passive 점검 룰 정의 — 정보수집 단계에서 수동 탐지에 사용할 시그니처·체크리스트 작성 |
| **P2** | 능동 Top10 룰 설계 및 측정 루프 주도 — 능동 스캔 엔진에 적용할 페이로드·탐지 로직 설계; 능동 점검(S3) 및 오탐 검증(S4) 사이클을 반복 주도하며 정밀도·재현율 측정 루프 운영 |
| **P3** | CVSS 산정 및 조치 가이드 검수 — 확정 취약점에 CVSS 점수 부여; 리포트 엔지니어 작성 조치 가이드의 기술적 정확성 검수 및 피드백 |
| **P4** | 인증 영역 점검·고도화 — 인증·세션·권한 관련 취약점(OWASP A01·A07 등) 심화 점검; 점검 룰·페이로드 고도화 |

## 7. 산출물 + DoD

| 산출물 | 형식 | 완료 기준 (Definition of Done) |
|--------|------|-------------------------------|
| 탐지 룰·시그니처 문서 | Markdown / YAML | OWASP Top10 전 항목 커버, 리뷰어 승인 |
| 능동 점검 결과 원본 | JSON / 로그 | 모든 후보 결함 목록화, 불변 감사로그 보존 |
| 확정 취약점 증거 패키지 | HTTP 요청·응답 캡처 + PoC 스크립트 | 재현 가능한 증거 첨부, 무기화 요소 제거 확인 |
| CVSS 점수 시트 | Markdown 표 | 각 취약점에 CVSS v3.1 벡터 문자열·점수 기재 |
| 조치 가이드 검수 의견 | 인라인 코멘트 / 문서 | 모든 기술 오류 지적·수정 확인 완료 |

## 8. 협업 인터페이스

| 협업 대상 | 인터페이스 방향 | 주요 내용 |
|-----------|----------------|-----------|
| **백엔드 / 인프라 엔지니어** | 수신 (Input) | 승인된 자산 인벤토리·스코프 문서 전달받음 |
| **리포트 엔지니어** | 송신 (Output) | 확정 취약점·증거·CVSS 전달; 조치 가이드 기술 검수 피드백 제공 |
| **프로젝트 오너** | 에스컬레이션 | 스코프 외 발견·DoS 위험 페이로드·윤리적 판단 필요 시 즉시 보고 |
| **QA / 재검증 담당** | 양방향 | S7 재검증 시 수정 후 재점검 결과 확인 및 최종 확정 협력 |
