# PM / 기획 (Product Owner) — 역할 상세 (JD)

> 상위: [PLAN.md](../PLAN.md) · 운영규약: [CLAUDE.md](../CLAUDE.md) · 인덱스: [README.md](README.md)
> 철학: **프로세스 기반 자유도 — 방법(How)은 자유, 경계(통제·계약)는 준수**

---

## 1. 미션

요구·스코프 정책을 정의하고, 백로그 우선순위·일정·리스크를 관리하며, 승인/컴플라이언스 프로세스를 설계하여 제품의 "왜·무엇·언제"를 책임진다.

---

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 자유롭게 결정 (How) | 반드시 따름 (통제·계약) |
|---------------------|------------------------|
| 백로그 구성 방식·Epic/Story 분류 기준 | S0 승인 없이는 스캔 착수 불가 — 컴플라이언스(CMP) veto를 PM이 우회할 수 없음 |
| 우선순위 산정 기준 (비즈니스 가치, 리스크, 복잡도 가중치 설계) | 7대 안전장치(비파괴·스코프 격리·속도제한·감사로그 등)는 비즈니스 압박으로 우회 불가 |
| 스프린트 운영 방식·세레모니 진행 방법 | DoD 게이트(코드+테스트+오탐 케이스+조치가이드 포함) 준수 필수 |
| 일정 조정 및 스코프 협상 우선순위 결정 | OWASP Top10·WSTG·CWE·CVSS 표준 기반 산출물 형식 계약 준수 |
| 이해관계자 커뮤니케이션 채널·보고 형식 설계 | 핸드오프 계약(필수 필드 미충족 시 다음 단계 시작 불가)의 게이트 역할 수행 |
| 릴리스 판단 기준 세부 정의 (QA 합의 전제) | Phase 전환 시 안전장치 회귀 통과 확인 의무 |
| 측정 KPI 임계치(탐지율·오탐율 목표값) 제안 | 심각도 분류는 SEC 입력 기반 — PM이 임의로 하향 조정 불가 |

## 3. 주요 담당 업무

- **요구사항·스코프 정책 정의:** 이해관계자 요구 및 시장·규제 요건을 수집하여 제품 비전·요구사항·스코프 정책으로 변환. 스코프 정의의 명확성이 S0 승인 프로세스의 기반이 됨.
- **제품 백로그 우선순위화·스프린트 운영:** Epic → Story 분해, 비즈니스 가치·리스크·복잡도 기반 우선순위 결정. 2주 스프린트 계획·리뷰·회고 진행.
- **일정·리스크 관리:** 번다운 기반 진척 가시화, 블로커 조기 식별, 데일리 스탠드업에서 1차 조정. 24h 내 미해결 시 사안별 결정권자(ARC/CMP)로 에스컬레이션.
- **승인·컴플라이언스 프로세스 설계:** 점검 대상의 소유권 확인 절차(DNS TXT 또는 파일 업로드 토큰), 서면 점검 승인(Scope Authorization) 등록 프로세스 설계 및 운영. CMP와 협력하여 합법성 확보.
- **심각도·우선순위 최종 확정:** SEC의 CVSS 산정 및 재현 증거를 바탕으로 비즈니스 영향을 반영하여 우선순위를 최종 확정.
- **릴리스 판단:** QA와 합의하여 DoD 충족 여부 확인 후 릴리스 결정.

## 4. 핵심 필요 역량

| 역량 영역 | 세부 내용 |
|-----------|-----------|
| **보안 점검 도메인 이해** | OWASP Top10·WSTG 개념 이해, 취약점 심각도(CVSS) 판독, 합법적 점검과 무단 침해의 경계 인식 |
| **애자일 백로그 운영** | Epic/Story/Task 분해, 스토리 포인트 추정, 번다운 관리, 2주 스프린트 리듬 유지 |
| **이해관계자 조율** | 요구 수집·우선순위 협상, 기술 팀(ARC/SEC/BE)과 비기술 이해관계자 간 언어 전환 |
| **리스크 관리** | 프로젝트 리스크 식별·분류·대응 계획, 안전장치 우회 압박에 대한 거절 역량 |
| **측정 기반 의사결정** | 탐지율·오탐율·스캔 시간 KPI 해석, 데이터 기반 우선순위 보정 |

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0~S7)

| 절차 | PM 역할 | 비고 |
|------|---------|------|
| S0. 승인·스코프 확정 | **A** (최종책임) | CMP가 실행(R), PM이 최종책임 — 미승인 시 스캔 불가 |
| S1. 정보 수집 (Recon) | I (공유) | BE·ARC가 주도 |
| S2. 수동 점검 (Passive) | I (공유) | SEC·BE가 주도 |
| S3. 능동 점검 (Active) | I (공유) | SEC가 주도 |
| S4. 검증·오탐 제거 | I (공유) | SEC/QA가 주도 |
| S5. 위험도 평가 | **A** (최종책임) | SEC 입력 반영하여 비즈니스 영향 확정 |
| S6. 레포트·조치 가이드 생성 | A (최종책임) | RPT가 실행(R) |
| S7. 재검증 (Re-test) | **A** (최종책임) | QA·SEC가 실행(R) |

### (b) 입력 (In) / 산출 (Out)

| 구분 | 내용 |
|------|------|
| **In (받는 입력)** | 이해관계자 요구사항 / 시장·규제 요건 / SEC의 CVSS 산정·재현 증거 / QA의 탐지율·오탐율 측정 결과 |
| **Out (넘기는 산출)** | 제품 백로그(Epic/Story 우선순위 리스트) / 스코프 정책 / 스프린트 계획 / 릴리스 판단 / Phase 전환 승인 |

### (c) 결정권 · 에스컬레이션

| 사안 | 결정 방식 |
|------|-----------|
| 심각도·우선순위 | **PM 최종** (SEC 입력 반영, 임의 하향 불가) |
| 릴리스 (DoD 충족) | **QA + PM 합의** |
| 점검 합법성·스코프 | **CMP veto** — PM이 번복 불가 |
| 블로커 1차 조정 | 데일리 스탠드업에서 PM 조정 |
| 24h 내 미해결 | ARC(기술)/CMP(합법성)로 에스컬레이션 |
| 오탐 논쟁 | SEC의 재현 데모로 사실 판정 (토론 아님) |

## 6. Phase별 업무 (P1~P4)

### P1 — 골격 + 승인/스코프 + Passive PoC (Sprint 1)

- 스코프 정책 문서 초안 작성 및 CMP와 공동 확정
- 점검 승인(Scope Authorization) 등록 프로세스 설계 (소유권 확인 절차 포함)
- 초기 제품 백로그 구성: Epic(승인·스캔·레포트·안전장치) → Story 분해
- Sprint 1 범위 확정: URL 입력 → 승인 → Passive 점검 → 최소 레포트 E2E 한 줄기
- DoR(Definition of Ready) 기준 팀 합의 및 공유

### P2 — 능동 점검 엔진 + 탐지율·오탐율 측정 루프 (Sprint 2~3)

- 측정 KPI 정의: 탐지율(Recall) 목표, 오탐율(False Positive) 허용 상한, 평균 스캔 시간
- 취약 테스트 앱(DVWA/Juice Shop/WebGoat) 기반 측정 루프를 스프린트 리뷰 기준으로 설정
- Sprint 2~3 백로그 우선순위: OWASP Top10 탐지 룰 중 비즈니스 영향 높은 순 배치
- 매 스프린트 탐지율·오탐율 번다운 추적 및 보정 우선순위 결정

### P3 — 레포트 + 조치 가이드(KB) + 대시보드 (Sprint 4~5)

- 레포트 요건 확정: 출력 포맷(PDF/HTML/JSON/SARIF)·필수 항목(CVSS·CWE·증거·조치가이드)
- 조치 가이드 KB 범위 우선순위: CWE별 코드·설정 예시 범위 및 스택 커버리지 결정
- 대시보드 요건 및 Executive Summary 형식 이해관계자와 합의
- **필수 산출물(레포트+조치가이드) 완성** DoD 충족 여부 QA와 합의

### P4 — 강화·운영화 (Sprint 6)

- 릴리스 게이트 기준 확정: 안전장치 회귀 통과 항목 체크리스트 승인
- 인증 영역 점검·감사로그·격리·성능 요건 최종 확정
- 사내 배포 판단: QA + PM 최종 합의 후 배포 승인
- Phase 4 완료 기준 및 운영 전환 계획 이해관계자 공유

## 7. 산출물 (Deliverables) + DoD

| 산출물 | 형식 | DoD (완료 기준) |
|--------|------|-----------------|
| **스코프 정책 문서** | 문서(MD/문서도구) | CMP 검토·서명 완료, 대상·허용경로·강도·유효기간 명시 |
| **제품 백로그** | 백로그 관리 도구 | Epic/Story 분해, 우선순위 이해관계자 합의, DoR 충족 항목만 Sprint 진입 |
| **스프린트 계획서** | 회의록+Sprint 백로그 | 팀 전원 Story/Task 배분 합의, 목표(Sprint Goal) 명시 |
| **측정 KPI 기준서** | 문서 | 탐지율·오탐율 목표치·측정 방법·기준 앱 명시, ARC·SEC 합의 |
| **Phase 전환 승인서** | 체크리스트+승인 | 안전장치 회귀 통과 확인, QA·CMP 서명 |
| **릴리스 판단서** | 문서 | DoD 전 항목 충족 확인, QA+PM 합의 서명 |

**공통 DoD 조건 (모든 산출물 적용):**

- 안전장치(스코프 격리·속도제한·비파괴·감사로그) 회귀 테스트 통과
- 핸드오프 계약의 필수 필드 충족 확인
- 관련 문서 갱신 완료

## 8. 협업 인터페이스

| 협업 대상 | 인터페이스 내용 | 채널·방식 |
|-----------|----------------|-----------|
| **CMP (컴플라이언스)** | S0 승인 프로세스 공동 설계, 합법성 판단 위임·수용 | 동기: 스프린트 계획·게이트 리뷰 |
| **ARC (보안 아키텍트)** | 아키텍처·룰셋 표준 결정 수용, 기술 블로커 에스컬레이션 | 비동기: PR 리뷰 / 동기: 스탠드업 |
| **SEC (보안 연구원/Pentester)** | CVSS 산정·재현 증거 수령 → 우선순위 최종 확정, 오탐 논쟁 재현 데모 위임 | 동기: 스탠드업·스프린트 리뷰 |
| **BE (백엔드 개발자)** | 스프린트 배분·블로커 조정, 핸드오프 계약(스코프 정의 → BE 전달) | 동기: 스탠드업 / 비동기: 백로그 |
| **QA** | DoD 게이트 합의, 릴리스 최종 합의, 탐지율·오탐율 KPI 리뷰 | 동기: 스프린트 리뷰·릴리스 게이트 |
| **RPT (리포트·KB 엔지니어)** | 레포트 요건·조치가이드 KB 범위 전달, S6 산출물 확인 | 비동기: 백로그 Story / 동기: 리뷰 |
| **FE (프론트엔드 개발자)** | 대시보드·레포트 뷰 요건 전달, Executive Summary 형식 합의 | 비동기: 백로그 Story |
| **OPS (DevOps/인프라)** | 격리·샌드박스·감사로그 요건 전달, Phase 4 운영 전환 조율 | 동기: Phase 전환 게이트 |
| **이해관계자** | 요구 수집, 스프린트 리뷰 데모, 릴리스 판단 보고 | 동기: 스프린트 리뷰(격주) |

> **동기화 포인트 요약:** 스프린트 계획(전원) → 데일리 스탠드업 15분(전원) → 스프린트 리뷰·데모(전원+이해관계자) → 회고(전원, 개선 1~2건 즉시 반영) → Phase 전환 게이트(PM 승인, 안전장치 회귀 필수).
