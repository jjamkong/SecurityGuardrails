# 백엔드 개발자 (Backend) — 역할 상세 (JD)

> 상위: [PLAN.md](../PLAN.md) · 운영규약: [CLAUDE.md](../CLAUDE.md) · 인덱스: [README.md](README.md)
> 철학: **프로세스 기반 자유도 — 방법(How)은 자유, 경계(통제·계약)는 준수**

## 1. 미션

스캔 잡 오케스트레이션·워커·큐와 크롤러·핑거프린팅·API를 구현하여 웹 취약점 스캐너의 실행 골격을 구축한다. 승인된 스코프 내에서 안전하고 재현 가능한 방식으로 대상 자산을 수집·식별하며, 하위 엔진(능동 스캐너)과 상위 레포트 레이어가 신뢰할 수 있는 데이터 파이프라인을 제공하는 것이 핵심 책임이다.

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 영역 | 자유도 (How — 자율 결정 가능) | 통제 (경계 — 반드시 준수) |
|------|-------------------------------|--------------------------|
| 큐·워커 구현 | 큐 시스템(Redis·Celery·BullMQ 등) 및 워커 아키텍처 자유 선택 | 잡 실행 전 스코프 유효성 검증 코드 필수 내장 |
| 크롤 전략 | 크롤 깊이·우선순위·파싱 방식·라이브러리 자율 결정 | 승인된 도메인·경로 외 요청 코드 레벨에서 차단 |
| API 설계 | 엔드포인트 구조·페이로드 스키마·버전 전략 자율 결정 | 모든 외부 요청에 불변 감사로그(타임스탬프·대상·요청자·결과) 기록 |
| 라이브러리·언어 선택 | 언어·프레임워크·서드파티 라이브러리 자율 선택 | 속도제한·지수 백오프 기본 활성화; DoS 유발 동시성 금지 |
| 내부 아키텍처 | 모듈 분리·레이어링·데이터 모델 자율 설계 | 비파괴 기본값 유지; 아키텍처 표준 변경 시 보안 아키텍트 승인 필요 |
| 외부 도구 연동 | ZAP·Nuclei 등 연동 방식·래핑 전략 자율 구현 | 합법성 판단이 필요한 도구·설정은 컴플라이언스 검토 후 적용 |

## 3. 주요 담당 업무

1. **잡 오케스트레이션·워커·큐 구현**
   - 스캔 잡 생성·스케줄링·상태 추적·재시도 로직 설계 및 구현
   - 워커 풀 관리, 동시성 제어, 잡 우선순위 큐 운영

2. **크롤러·자산 식별·기술 핑거프린팅**
   - 대상 URL 기반 링크 수집·엔드포인트 열거·파라미터 식별
   - 기술 스택 핑거프린팅(헤더·응답·파비콘 해시 등)으로 자산 인벤토리 생성

3. **스캔·결과 API 개발**
   - 스캔 요청·상태 조회·결과 조회·레포트 트리거 등 내부/외부 API 구현
   - 취약점 데이터 스키마 정의 및 연구원·레포트 레이어와 인터페이스 계약 유지

4. **안전장치 코드 내장**
   - 스코프 격리: 승인된 대상 외 요청을 코드 레벨에서 차단
   - 속도제한·백오프: 대상 서버 과부하 방지
   - 감사로그: 모든 외부 요청 불변 로그 기록
   - 비파괴 기본값: 설정 누락 시 안전 모드로 동작

## 4. 핵심 필요 역량

- **비동기 작업·큐 처리**: 분산 잡 큐(Redis·Celery·BullMQ 등) 설계·운영 경험; 잡 상태 머신, 재시도·데드레터 처리
- **HTTP 스택·동시성 제어**: HTTP/HTTPS 요청 심층 이해, 커넥션 풀·타임아웃·리다이렉트 제어, 동시 요청 수 조절
- **안전한 외부 요청 설계**: 속도제한·지수 백오프·서킷브레이커 구현; SSRF·오픈 프록시 방지 패턴
- **크롤링·파싱**: HTML 파싱·링크 추출·JavaScript 렌더링 필요 여부 판단; robots.txt 준수 설계
- **API 설계·문서화**: RESTful 또는 GraphQL API 설계, OpenAPI 스펙 작성, 내부 계약 유지
- **보안 코딩 기초**: 입력 검증·스코프 체크·감사로그 패턴; OWASP Top10·CWE 기초 이해

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0~S7)

| 절차 | 내용 | 백엔드 역할 |
|------|------|------------|
| S0 | 승인·스코프 정의 | **I** (수신·확인) |
| S1 | 정보수집·자산 인벤토리 | **R** (주 실행 책임) |
| S2 | 수동 점검 | **R** (크롤·API 데이터 제공) |
| S3 | 능동 점검 | **C** (엔진 연동 지원) |
| S4 | 검증·오탐 제거 | **C** (재현 요청 지원) |
| S5 | 위험도 산정 | **–** (비관여) |
| S6 | 레포트 생성 | **–** (비관여) |
| S7 | 재검증 | **C** (재스캔 실행 지원) |

> R=실행 책임, A=최종 승인, C=협의, I=통보, –=비관여

### (b) 인풋 / 아웃풋

| 방향 | 내용 |
|------|------|
| **In (수신)** | S0 스코프 정의 — 대상 도메인·허용 경로·스캔 강도·유효기간·승인 ID |
| **Out (제공)** | S1 자산 인벤토리 — URL 목록·엔드포인트·파라미터·기술 핑거프린트 → 보안 연구원에게 전달 |

### (c) 결정권·에스컬레이션

| 사항 | 결정 주체 |
|------|-----------|
| 구현 방식 (큐·크롤·API 설계·라이브러리) | 백엔드 개발자 자율 결정 |
| 아키텍처 표준 변경 | 보안 아키텍트 승인 필요 |
| 합법성 관련 도구·설정 | 컴플라이언스 검토 후 적용 |
| 스코프 외 요청 필요 판단 | 즉시 에스컬레이션 (절대 자율 실행 금지) |

## 6. Phase별 업무

| Phase | 주요 업무 |
|-------|-----------|
| **P1** 골격·승인/스코프·Passive PoC | 잡 골격(큐·워커·상태 머신) 구현; 크롤러 기본 버전; 스코프 격리 코드 내장; 감사로그 기초 연결 |
| **P2** 능동 엔진·측정 루프 | ZAP·Nuclei 등 능동 스캐너 래핑·연동; 속도제한·백오프 강화; 잡 재시도·오류 처리 고도화 |
| **P3** 레포트·KB·대시보드 | 취약점 결과 API 완성; 레포트 레이어·대시보드와 인터페이스 계약 구현; 데이터 스키마 안정화 |
| **P4** 인증·감사·격리·성능→배포 | 인증 세션 주입 스캔 지원; 스코프 격리 강화 검증; 성능 튜닝·부하 테스트; 배포 파이프라인 연결 |

## 7. 산출물 + DoD

| 산출물 | 완료 기준 (Definition of Done) |
|--------|-------------------------------|
| 잡 오케스트레이터·워커 | 잡 생성→실행→완료·실패 상태 전이 테스트 통과; 스코프 외 요청 시 차단 확인 |
| 크롤러·핑거프린터 | 승인된 대상에서 URL·엔드포인트·파라미터·기술스택 추출 정확도 검증; robots.txt 준수 확인 |
| 스캔·결과 API | OpenAPI 스펙 작성 완료; 연구원·레포트 레이어와 인터페이스 계약 서명; E2E 테스트 통과 |
| 스코프 격리 코드 | 승인 ID 없는 요청 100% 차단 단위 테스트; 감사로그 누락 없음 확인 |
| 감사로그 | 모든 외부 요청에 타임스탬프·대상·요청자·결과 기록; 불변성(수정 불가) 확인 |
| 속도제한·백오프 | 설정값 초과 시 자동 스로틀링 동작 확인; 기본값 미설정 시 안전 모드 동작 확인 |
