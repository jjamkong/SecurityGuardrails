> 상위: [PLAN.md](../PLAN.md) · 운영규약: [CLAUDE.md](../CLAUDE.md) · 인덱스: [README.md](README.md)
> 철학: **프로세스 기반 자유도 — 방법(How)은 자유, 경계(통제·계약)는 준수**

## 1. 미션

스캔 현황·취약점 결과·레포트를 사람이 빠르게 이해하고 조치하도록 대시보드/뷰로 표현한다. 분석 파이프라인이 생성한 데이터를 최종 사용자(보안 담당자·운영자·경영진)가 즉시 판단·행동할 수 있는 화면으로 번역하는 것이 이 역할의 핵심이다.

---

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 영역 | 자유 (How — 자율) | 통제 (Boundary — 반드시 준수) |
|------|-------------------|-------------------------------|
| UI/UX 설계 | 컴포넌트 구조·레이아웃·인터랙션 방식을 자유롭게 결정 | 권한별(역할별) 화면 노출 제어 정책을 반드시 준수 |
| 시각화 방식 | 차트·표·카드 등 표현 방식과 디자인 시스템 선택 자유 | 심각도 라벨·색상은 CVSS 기준 표준 체계 일관 적용 |
| 컴포넌트·라이브러리 | 프레임워크·UI 라이브러리·번들러 등 기술 스택 선택 자유 | 민감정보(페이로드·자격증명 단편 등) 마스킹 표시 의무 |
| 데이터 표현 | 필터·정렬·드릴다운 UX 설계 방식 자유 | 악용 가능한 원시 페이로드의 부주의한 화면 노출 방지 |
| 내보내기 형식 | PDF·CSV·JSON 등 내보내기 포맷 및 UI 흐름 자유 설계 | 내보내기 대상·범위는 역할 권한 정책 내로 제한 |
| 접근성·반응형 | 구현 방식·우선순위 자율 결정 | WCAG 기준 접근성 최소 요건 충족 (P4 완성 기준) |

---

## 3. 주요 담당 업무

1. **대시보드** — 스캔 진행 현황, 자산별 취약점 추이, 미해결 SLA 현황을 실시간 표시
2. **레포트 뷰** — 취약점 레포트 열람·필터·드릴다운 UI 구현
3. **사용자·권한 화면** — 사용자 계정·역할 관리 및 권한별 접근 제어 화면
4. **감사 로그 열람 화면** — 불변 감사 로그 조회·검색·내보내기 UI 구현
5. **내보내기 UI** — 레포트 및 로그를 PDF·CSV·JSON 등으로 내보내는 기능 제공

---

## 4. 핵심 필요 역량

- **데이터 시각화** — 차트·그래프·히트맵 등을 이용한 취약점 추이·분포 표현 능력
- **상태 관리** — 스캔 진행 상태·폴링·실시간 업데이트를 안정적으로 처리하는 상태 관리 설계
- **표/차트 UI** — 대용량 취약점 목록의 필터·정렬·페이지네이션·드릴다운 구현
- **접근성** — WCAG 기준 접근성 요건 충족, 키보드 네비게이션·스크린리더 대응
- **보안 UI 감각** — 민감정보 마스킹·권한별 노출 제어 등 보안 요건을 UI 레이어에서 구현

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0~S7)

| 단계 | 설명 | 프론트엔드 |
|------|------|-----------|
| S0 | 승인·스코프 확정 | – |
| S1 | 정보 수집 (패시브) | – |
| S2 | 수동 분석 | – |
| S3 | 능동 점검 | – |
| S4 | 취약점 검증 | – |
| S5 | 위험도 평가 (CVSS) | – |
| S6 | 레포트 생성 | **I** (산출물 소비·시각화) |
| S7 | 재검증·종료 | – |

> 파이프라인 단계의 직접 소유는 없으나, S6에서 리포트 엔지니어가 생성한 산출물을 소비하여 사용자에게 시각화하는 역할을 담당한다.

### (b) In / Out

| 방향 | 내용 |
|------|------|
| **In** | 리포트 엔지니어의 레포트 데이터 (JSON/SARIF) · 스캔 상태 API · 감사 로그 API |
| **Out** | 사용자에게 보이는 대시보드·레포트·권한·감사 화면 및 내보내기 UI |

### (c) 결정권 · 에스컬레이션

- **결정권**: UI/UX 구조·컴포넌트·시각화 방식·디자인 시스템은 자율 결정
- **에스컬레이션 필요**: 권한별 노출·마스킹 정책 변경, 새로운 민감정보 유형 노출 여부, 내보내기 범위 확대 요청 시 → 보안 책임자(Security Lead) 승인 필요

## 6. Phase별 업무

| Phase | 목표 | 프론트엔드 업무 |
|-------|------|----------------|
| **P1** | MVP 스캐너 동작 | 최소 결과 뷰 — JSON 응답을 읽을 수 있는 형태로 표시 |
| **P2** | 파이프라인 안정화 | 스캔 현황 모니터링 대시보드 · 기본 측정 지표 시각화 |
| **P3** | 레포트+KB+대시보드 완성 | 레포트 뷰·필터·드릴다운·내보내기 UI 완성 |
| **P4** | 운영 고도화 | 권한·사용자 관리 화면 · 감사 로그 화면 · 접근성 완성 |

## 7. 산출물 + DoD

| 산출물 | 완료 기준 (Definition of Done) |
|--------|-------------------------------|
| 스캔 현황 대시보드 | 진행률·자산별 상태·SLA 미해결 건수 실시간 표시, 권한별 노출 제어 검증 완료 |
| 취약점 레포트 뷰 | 필터(심각도·자산·날짜)·정렬·드릴다운·CVSS 표준 라벨 색상 일관 적용 확인 |
| 내보내기 UI | PDF·CSV·JSON 내보내기, 역할 권한 내 범위 제한, 민감정보 마스킹 적용 확인 |
| 사용자·권한 화면 | 역할 CRUD, 권한별 화면 노출 제어 E2E 검증 |
| 감사 로그 화면 | 불변 로그 조회·검색·내보내기, 원시 페이로드 직접 노출 없음 확인 |
| 접근성 준수 | WCAG 2.1 AA 기준 핵심 화면 통과 (P4 완성 기준) |
