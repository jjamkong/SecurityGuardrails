## 1. 미션

스캐너 엔진 아키텍처·룰셋 체계·안전장치를 설계하고 기술 표준을 수호한다.

보안 아키텍트(ARC)는 SecurityGuardrails가 **"합법·방어용"** 이라는 정체성을 기술 수준에서 보장하는 최후 방어선이다. 기능 속도보다 안전장치의 견고성을 우선하며, 모든 탐지·분석 모듈이 일관된 표준(OWASP Top10·WSTG·CWE·CVSS) 위에서 동작하도록 설계 기준을 정립하고 유지한다.

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 자유 (How — 역할자 재량) | 통제 (비협상 — 반드시 준수) |
|--------------------------|------------------------------|
| 기술 스택 선택: ZAP/Nuclei 래핑 방식 vs. 자체 엔진 구현 비율 결정 | 스코프 격리는 아키텍처 강제 내장: 화이트리스트 외 도메인·경로로 크롤러·페이로드가 유출되지 않도록 엔진 레벨에서 차단 |
| 모듈 경계 설계: 크롤러·Passive·Active·검증 모듈 간 인터페이스 및 분리 방식 | 속도 제한은 비협상: 동시 요청 수·RPS 상한·백오프 로직을 안전장치 레이어에 강제 구현 |
| 룰 구조 설계: 시그니처 포맷, 룰 메타데이터 스키마, 우선순위 체계 | 비파괴(Non-destructive) 기본값 준수: DELETE/DROP·대량 요청·서비스 마비 유발 페이로드는 기본 비활성, 명시적 동의 플래그 없이 실행 불가 |
| 확장 방식 결정: 플러그인 아키텍처, 템플릿 기반 룰 로딩, 핫-리로드 여부 | 모든 탐지 결과는 표준 매핑 가능: 산출 Finding마다 OWASP 분류·CWE ID·CVSS 벡터가 연결 가능한 구조여야 함 |
| OSS 선택: Wappalyzer류 핑거프린터·ZAP·Nuclei 외 대안 도구 도입 여부 | ARC 결정 사항 변경 시 ARC 재승인 필요: 룰셋·아키텍처 표준 변경은 반드시 ARC가 최종 승인 |
| 내부 동시성 모델: 워커 스레드 수·큐 구조·격리 컨테이너 세부 설계 | 합법성 충돌 시 컴플라이언스(CMP) 우선: 아키텍처 표준과 법적 요건이 충돌하면 CMP 판단이 선행 |
| Phase 내 설계 순서·작업 분할: Phase 범위 내 작업 우선순위 ARC 자율 결정 | 안전장치 회귀 테스트 필수 통과: Phase 전환 및 스프린트 DoD에 안전장치 회귀 결과 포함 |

## 3. 주요 담당 업무

1. **엔진 아키텍처 설계**
   - 스캔 파이프라인(S1 크롤러 → S2 Passive → S3 Active → S4 검증) 모듈 경계와 인터페이스 정의
   - Job Orchestrator와 각 모듈 간 호출 계약(입출력 스키마, 오류 처리, 타임아웃) 설계
   - 동시성·격리 모델: 스캔 간 자원 충돌 방지, 격리 컨테이너/워커 아키텍처 설계

2. **룰셋 체계·시그니처 표준 정의**
   - 탐지 룰 메타데이터 스키마(룰 ID·유형·OWASP 분류·CWE·CVSS 벡터·심각도·페이로드·검증 방법) 정의
   - 검증된 OSS 템플릿(Nuclei 템플릿·ZAP 스캔 규칙) 래핑 전략 및 자체 룰 추가 기준 결정
   - 부록 A 초기 룰셋 시드를 기반으로 룰셋 분류 체계(Passive/Active/Verify) 수립

3. **안전장치 아키텍처 내장 설계**
   - 스코프 격리 레이어: 화이트리스트 적용, out-of-scope 링크 추적 차단을 엔진 레벨에서 강제
   - 속도 제한·백오프: RPS 상한, 동시 요청 상한, 지수 백오프 구현 기준 정의
   - 비파괴 기본값 강제: 위험 페이로드 활성화를 위한 명시적 동의 플래그·프로파일 게이트 설계
   - 불변 감사로그 연계: 스캔 행위(누가·언제·어디에·어떤 강도로) 기록 포인트 정의(실행은 OPS)

4. **기술 표준 수호 및 코드 게이트**
   - PR 리뷰 시 룰·엔진 코드가 아키텍처 표준에 부합하는지 검수(비동기 코드 게이트)
   - 탐지 결과 스키마(Finding 객체)가 OWASP/CWE/CVSS 매핑 가능 구조인지 지속 확인
   - Phase 전환 전 안전장치 회귀 테스트 기준 정의 및 결과 검토

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0~S7)

| 절차 | PM | **ARC** | SEC | BE | FE | RPT | OPS | QA | CMP |
|------|----|---------|-----|----|----|-----|-----|----|-----|
| S0 승인·스코프 | A | **C** | I | I | – | – | I | – | R |
| S1 정보수집 | I | **A** | C | R | – | – | C | – | I |
| S2 수동점검 | I | **A** | R | R | – | – | C | I | – |
| S3 능동점검 | I | **A** | R | C | – | – | C | I | I |
| S4 검증·오탐제거 | I | **C** | A/R | C | – | – | – | R | – |
| S5 위험도평가 | A | **C** | R | – | – | C | – | – | I |
| S6 레포트·조치가이드 | A | **C** | C | – | I | R | – | I | I |
| S7 재검증 | A | **–** | R | C | – | C | C | R | – |

> R=실행 · A=최종책임 · C=자문 · I=공유 · –=비관여

### (b) In / Out

| 방향 | 내용 |
|------|------|
| **Input (받는 것)** | 제품 요구사항·스코프 정책(PM), 점검 승인 레코드(CMP), 기술 스택 제약(OPS) |
| **Output (만들어 넘기는 것)** | 엔진 아키텍처 설계서, 룰셋 표준 스키마, 안전장치 설계서, 모듈 인터페이스 계약, 코드 게이트 검수 의견 |

### (c) 결정권 · 에스컬레이션

| 사안 | 결정 주체 | 비고 |
|------|-----------|------|
| 룰셋·아키텍처 표준 (최종) | **ARC** | 일관성·안전장치 보장 최우선 |
| 기술 선택(OSS 래핑 vs 자체 구현) | **ARC** | How는 ARC 재량 |
| 안전장치 완화 요청 | **ARC 거부 또는 PM/CMP 합의 필요** | 비협상 항목은 단독 완화 불가 |
| 합법성 충돌 | **CMP 우선, ARC는 C 역할** | 0장 대원칙 선행 |
| 표준 충돌(역할 간 이견) | **ARC가 표준 판정** → 24h 내 미해결 시 SEC 재현 데모로 사실 판정 | 에스컬레이션 경로 |

## 6. Phase별 업무 (P1~P4)

### P1 — 골격 아키텍처 + 안전장치 기준선 (Sprint 1)

| 구분 | 세부 내용 |
|------|-----------|
| 목표 | E2E 한 줄기(URL 입력 → Passive 점검 → 최소 레포트) 관통 가능한 골격 아키텍처 확립 |
| 주요 업무 | 파이프라인 모듈 경계 정의(크롤러·Passive·리포터 인터페이스 계약) / 안전장치 기준선 설계(스코프 격리·속도제한·비파괴) / Finding 객체 초기 스키마 정의 / 기술 스택 선택 결정(ADR 작성) |
| 핵심 산출물 | 골격 아키텍처 문서, 안전장치 설계서 v0.1, Finding 스키마 v0.1, 모듈 인터페이스 계약 |
| DoD 관련 | 안전장치 기준선(스코프 격리·속도제한) 구현 검증 완료 후 P2 전환 승인 |

### P2 — 능동 엔진 + 룰셋 체계 (Sprint 2~3)

| 구분 | 세부 내용 |
|------|-----------|
| 목표 | ZAP/Nuclei 래핑 기반 OWASP Top10 능동 점검 엔진 가동 및 룰셋 체계 확립 |
| 주요 업무 | 능동 점검 모듈(S3) 아키텍처 설계 / 룰셋 메타데이터 스키마 확정 / OSS 템플릿 래핑 전략 실행 / 탐지율·오탐율 측정 루프 지원(측정 기준 정의) / PR 코드 게이트(룰 표준 준수 검수) |
| 핵심 산출물 | 능동 엔진 설계서, 룰셋 표준 스키마 v1.0, OSS 래핑 ADR, 탐지 측정 기준 정의서 |
| DoD 관련 | 취약 테스트 앱(DVWA/Juice Shop)에서 능동 점검 동작 확인, 안전장치 회귀 통과 |

### P3 — CVSS·KB 연계 아키텍처 (Sprint 4~5)

| 구분 | 세부 내용 |
|------|-----------|
| 목표 | CVSS 산정·CWE 매핑·조치 가이드 KB 연계 아키텍처 완성(필수 산출물 구조 완성) |
| 주요 업무 | Finding ↔ RemediationGuide 연계 모델 설계 / CVSS 벡터 자동 제안 아키텍처 / KB(CWE별 조치 가이드) 데이터 구조 설계 / SARIF·PDF·HTML 출력 모듈 인터페이스 정의 |
| 핵심 산출물 | CVSS 연계 아키텍처 설계서, KB 데이터 모델 설계서, 출력 포맷 인터페이스 계약 |
| DoD 관련 | 레포트에 OWASP/CWE/CVSS 매핑 포함 확인, 조치 가이드 KB 연결 동작 검증 |

### P4 — 인증·격리·성능 아키텍처 (Sprint 6)

| 구분 | 세부 내용 |
|------|-----------|
| 목표 | 인증 영역 점검, 스캔 격리 강화, 성능 튜닝 아키텍처 완성 → 사내 배포 준비 |
| 주요 업무 | 인증 세션/토큰 주입 아키텍처 설계(보안 전달 방식) / 멀티-테넌트 격리 강화 설계 / 성능 상한(동시 스캔 수·RPS) 기준 정의 및 튜닝 포인트 식별 / 전수 안전장치 회귀 기준 최종 확정 |
| 핵심 산출물 | 인증 점검 아키텍처 설계서, 격리·성능 설계서, 전수 안전장치 회귀 체크리스트 |
| DoD 관련 | 안전장치 전수 회귀 통과, 격리 네트워크 검증 완료, PM+QA 배포 승인 |

## 7. 산출물 + DoD

### 주요 산출물 목록

| 산출물 | 형식 | 최초 생성 Phase |

| 모듈 인터페이스 계약 | API 명세(입출력·오류·타임아웃) | P1 |
| 기술 선택 ADR | Markdown (ADR 포맷) | P1 |
| 룰셋 표준 스키마 | JSON Schema / YAML 스키마 | P2 |
| OSS 래핑 전략 ADR | Markdown | P2 |
| CVSS·KB 연계 아키텍처 | Markdown + 데이터 모델 | P3 |
| 출력 포맷 인터페이스 계약 | Markdown / OpenAPI 일부 | P3 |
| 인증·격리·성능 설계서 | Markdown | P4 |
| 전수 안전장치 회귀 체크리스트 | Markdown / 체크리스트 | P4 |

### DoD (완료 기준)

- [ ] 설계서는 모듈 경계·인터페이스 계약·오류 처리를 포함하며 BE/SEC가 즉시 구현 착수 가능한 수준
- [ ] 모든 Finding 스키마는 OWASP 분류·CWE ID·CVSS 벡터 필드를 포함
- [ ] 안전장치(스코프 격리·속도제한·비파괴 기본값) 설계가 아키텍처에 강제 내장되어 있으며, 우회 경로가 없음을 설계 리뷰에서 확인
- [ ] ADR에 결정 배경·대안·트레이드오프가 기록됨
- [ ] PR 코드 게이트 검수 완료(룰·엔진 코드가 아키텍처 표준 준수)
- [ ] Phase 전환 시 안전장치 회귀 체크리스트 통과 확인

## 8. 협업 인터페이스

| 협업 대상 | 인터페이스 방식 | 주요 내용 |
|-----------|----------------|-----------|
| **PM** | 스프린트 계획·회고, 비동기 문서 리뷰 | 요구사항·스코프 정책 수신 / 아키텍처 제약·리스크 공유 |
| **SEC (취약점 연구원)** | PR 코드 게이트, 설계 리뷰, 데일리 스탠드업 | 룰셋 스키마 기준 전달 / 탐지 로직 표준 준수 여부 검수 / 오탐 논의 시 재현 데모 요청 |
| **BE (백엔드 개발자)** | 모듈 인터페이스 계약 문서, PR 검수 | 엔진 아키텍처 설계 인계 / 안전장치 구현 검수 / 동시성·격리 설계 가이드 |
| **OPS (DevOps)** | 설계서 공유, 아키텍처 리뷰 | 격리 컨테이너·네트워크 요건 전달 / 감사로그 기록 포인트 정의 |
| **QA** | 안전장치 회귀 기준 문서, Phase 전환 체크리스트 | 안전장치 회귀 테스트 기준 제공 / DoD 회귀 결과 수신 |
| **RPT (리포트·KB 엔지니어)** | Finding 스키마·CVSS·KB 연계 아키텍처 문서 | 출력 포맷 인터페이스 계약 / CWE 매핑 구조 정의 전달 |
| **CMP (컴플라이언스)** | 에스컬레이션, 합법성 충돌 시 협의 | 스코프 정책·합법성 요건 수신 / 안전장치 설계가 법적 요건 충족하는지 자문 요청 |

> **핵심 협업 원칙:** ARC는 설계 기준을 문서로 명확히 하고 PR 코드 게이트로 집행한다. 구두 합의는 ADR 또는 인터페이스 계약 문서로 반드시 기록한다. 표준 충돌 시 ARC가 판정하되, 합법성 사안은 CMP에 선행 위임한다.
