## 1. 미션

스캔 워커를 격리·샌드박스 환경에서 안전하게 구동하고, 시크릿 관리·불변 감사로그·모니터링 등 운영 기반 인프라 전반을 제공한다. 보안 안전장치(격리·속도제한·감사로그)를 소프트웨어 레이어에 맡기지 않고 **인프라 레벨에서 강제**함으로써, 어떤 코드 버그가 발생하더라도 안전 경계가 무너지지 않도록 보장하는 것이 이 역할의 핵심 가치다.

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 영역 | 자유 (How — 자율 결정) | 통제 (What/Why — 비협상) |
|------|------------------------|--------------------------|
| 인프라 스택 | 컨테이너 런타임·오케스트레이터·클라우드 공급자·IaC 도구를 팀 판단으로 선택 | 스캔 워커는 반드시 격리 네트워크에서 동작해야 하며, 트래픽이 사내망·타 시스템에 영향을 주어서는 안 됨 |
| 배포·스케일링 방식 | 롤링·블루-그린·카나리 등 배포 전략과 오토스케일 정책을 자율 설계 | 감사로그는 불변(append-only) 저장소에 보관해야 하며, 임의 삭제·수정 불가 |
| 관측성·모니터링 도구 | 로깅 스택(ELK·Loki 등), 메트릭(Prometheus·Datadog 등), 알람 채널을 자유롭게 선택 | 시크릿(API 키·자격증명)은 평문 환경 변수나 코드 내 하드코딩 금지, 시크릿 매니저 경유 필수 |
| 취약 테스트 앱 구동 방식 | DVWA·Juice Shop 등 타겟 앱의 구동 방식 및 이미지 관리 자율 | 취약 테스트 앱은 격리 네트워크에서만 구동, 외부 인터넷·사내망 접근 차단 |
| 속도제한 구현 방법 | RPS 상한·동시접속 제한·백오프 구현 기술 자유 선택 | DoS 방지용 속도제한은 인프라 레이어에서 강제 적용(공통 통제 규칙 4번) |

## 3. 주요 담당 업무

1. **스캔 워커 격리·샌드박스·스케일링**
   - 컨테이너 기반 격리 실행 환경 구축 (격리 네트워크 세그먼트, egress 제어)
   - 스캔 워커 자동 스케일링 정책 설계·운영
   - 워커 생명주기(프로비저닝·회수·재사용) 관리

2. **시크릿 관리**
   - 시크릿 매니저 도입·운영 (API 키, DB 자격증명, 스캔 토큰 등)
   - 시크릿 순환(rotation) 정책 수립 및 자동화

3. **불변 감사로그 적재·보존**
   - append-only 감사로그 저장소 구축 (누가·언제·어떤 대상을·어떤 강도로 스캔했는지)
   - 로그 보존 기간 정책 적용, 자동 파기 파이프라인 구성

4. **관측성 (로깅·메트릭·알람)**
   - 스캔 워커·API 서버·큐의 로그 수집·집계 파이프라인 구축
   - 핵심 메트릭(스캔 완료율, 에러율, 큐 깊이, RPS) 대시보드 구성
   - 임계값 초과·이상 징후 알람 설정

5. **취약 테스트 앱의 격리 구동 환경**
   - DVWA·OWASP Juice Shop 등 로컬 취약 앱을 격리 환경에서 구동
   - 테스트 앱이 외부 또는 사내망에 노출되지 않도록 네트워크 정책 강제

6. **속도제한 인프라 강제**
   - API 게이트웨이 또는 네트워크 레이어에서 RPS 상한·동시 요청 제한 적용

## 4. 핵심 필요 역량

| 분류 | 세부 역량 |
|------|-----------|
| 컨테이너·격리 네트워크 | Docker / Kubernetes, 네트워크 폴리시(NetworkPolicy), egress 제어, 샌드박스 런타임(gVisor·Kata 등) |
| 관측성 | 로그 집계(ELK·Loki), 메트릭(Prometheus·Grafana), 분산 트레이싱, 알람 설계 |
| 시크릿 / 보안 운영 | HashiCorp Vault·AWS Secrets Manager·K8s Secret 암호화, 시크릿 순환 자동화 |
| IaC · 자동화 | Terraform·Pulumi·Helm, CI/CD 파이프라인 구성 |
| 보안 기본 지식 | 네트워크 세그멘테이션, 최소 권한 원칙, append-only 스토리지 패턴 |

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0 ~ S7)

| 절차 | 이 역할 | 설명 |
|------|---------|------|
| S0 스캔 요청 수신·승인 검증 | I | 승인 흐름 정보 수신 |
| S1 스코프 파싱·큐 적재 | C | 큐 인프라 설계 참여 (자문) |
| S2 크롤링·자산 식별 | C | 워커 격리 환경 제공 (자문) |
| S3 취약점 분석·페이로드 실행 | C | 샌드박스·속도제한 인프라 강제 (자문) |
| S4 증거 수집·정규화 | – | 해당 없음 |
| S5 CVSS 채점·위험도 평가 | – | 해당 없음 |
| S6 레포트·조치가이드 생성 | – | 해당 없음 |
| S7 결과 저장·알림·감사로그 적재 | C | 감사로그 저장소·알림 인프라 운영 (자문) |

> R=Responsible(실행), A=Accountable(최종 책임), C=Consulted(자문), I=Informed(공유), –=해당 없음

### (b) Input / Output

| 방향 | 내용 |
|------|------|
| **Input (받는 것)** | 아키텍처 설계서, 안전장치 요건 정의, 스캔 워커 컨테이너 이미지, 감사로그 스키마 |
| **Output (제공하는 것)** | 격리 실행 환경, 불변 감사로그 저장소, 모니터링 대시보드·알람, 시크릿 관리 인프라, 속도제한 정책 |

### (c) 결정권 · 에스컬레이션

- **자율 결정 가능:** 인프라 스택 선택, 배포 방식, 스케일링 정책, 관측 도구 선정
- **비협상 요건 (변경 시 에스컬레이션 필수):**
  - 워커 격리 요건 완화 → PL(프로젝트 리더) + 보안 리드 동의 필수
  - 감사로그 불변성 보장 수준 변경 → PL 승인 필수
  - 취약 테스트 앱의 네트워크 정책 변경 → PL + 보안 리드 동의 필수

## 6. Phase별 업무

| Phase | 주요 업무 |
|-------|-----------|
| **P1** 인증·로컬 실행 환경 | 로컬 격리 실행 환경 구축 (Docker Compose 기반 격리 네트워크), 취약 테스트 앱(DVWA·Juice Shop) 격리 구동, 기본 로깅 파이프라인 초기화 |
| **P2** 감사·워커 스케일 | 스캔 워커 컨테이너 스케일링 인프라 구성, 워커 메트릭 수집 파이프라인(RPS·큐 깊이·에러율) 구축, 속도제한 인프라 레이어 강제 적용 |
| **P3** 격리 강화·리포트 인프라 | 리포트·증거 저장 인프라 구성, 보존 기간 정책 및 자동 파기 파이프라인, 감사로그 append-only 저장소 운영 강화 |
| **P4** 성능·배포 | 격리 강화 최종 검증, 감사로그 무결성 점검, 성능 최적화(워커 풀·캐싱), 프로덕션 배포 파이프라인 완성 |

## 7. 산출물 + DoD (Definition of Done)

| 산출물 | DoD 기준 |
|--------|----------|
| 격리 실행 환경 | 스캔 워커 트래픽이 격리 네트워크 외부(사내망·인터넷)로 유출되지 않음을 네트워크 정책 테스트로 확인 |
| 불변 감사로그 저장소 | 로그 레코드 추가는 가능하나 수정·삭제가 인프라 레벨에서 차단됨을 검증 |
| 시크릿 관리 인프라 | 평문 시크릿이 코드·환경변수·이미지에 존재하지 않음, 시크릿 매니저 경유 확인 |
| 관측성 대시보드 | 스캔 완료율·에러율·RPS·큐 깊이 메트릭이 실시간으로 표시되고 알람이 동작 |
| 취약 테스트 앱 격리 환경 | 테스트 앱이 외부·사내망에 노출되지 않음을 네트워크 접근 테스트로 확인 |
| 속도제한 인프라 강제 | RPS 상한 초과 요청이 인프라 레이어에서 차단됨을 부하 테스트로 확인 |

## 8. 협업 인터페이스

| 협업 대상 | 인터페이스 내용 |
|-----------|----------------|
| **백엔드 / 스캔 엔진** | 워커 컨테이너 이미지 스펙 협의, 큐(메시지 브로커) 인터페이스 정의, 환경 변수·시크릿 주입 방식 합의 |
| **보안 설계** | 격리 요건·감사로그 스키마·속도제한 임계값 입력 수신, 인프라 구현 결과 피드백 제공 |
| **프론트엔드 / API** | API 게이트웨이 속도제한 정책 공유, 배포 환경(스테이징·프로덕션) URL 및 상태 알림 |
| **PL (프로젝트 리더)** | Phase별 인프라 준비 상태 보고, 비협상 요건 변경 시 에스컬레이션 채널 |
| **공통 통제 준수 보고** | 7대 규칙(격리·감사로그·속도제한·시크릿) 이행 현황을 정기 점검 시 증적 제출 |
