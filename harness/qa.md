# QA / 검증 (Quality Assurance) — 역할 상세 (JD)

> 상위: [PLAN.md](../PLAN.md) · 운영규약: [CLAUDE.md](../CLAUDE.md) · 인덱스: [README.md](README.md)
> 철학: **프로세스 기반 자유도 — 방법(How)은 자유, 경계(통제·계약)는 준수**

## 1. 미션

의도적 취약 앱(OWASP Juice Shop · DVWA · WebGoat, 격리 환경 전용)을 대상으로 스캐너의 **탐지율(Recall)** 과 **오탐율(False Positive Rate)** 을 측정해 신뢰도를 수치로 끌어올린다. 동시에 공통 통제 7대 안전장치의 회귀를 매 스프린트 검증하며, PM과 합의된 DoD 기준을 충족할 때 "릴리스 가능" 판정을 내린다.

## 2. 자유도 ↔ 통제 경계 (Autonomy within Guardrails)

| 구분 | 내용 |
|------|------|
| **자유 — 테스트 시나리오 설계** | 취약 테스트 앱에 대한 시나리오 구성, 케이스 우선순위, 커버리지 전략을 QA가 독립 결정한다. |
| **자유 — 측정 방법** | 탐지율·오탐율 산출 공식, 샘플링 방식, 통계 처리 기준을 자율 선택한다. |
| **자유 — 자동화 도구 선택** | 회귀 자동화 프레임워크·CI 연동 방식·리포팅 형식을 QA가 결정한다. |
| **통제 — 격리 환경 전용** | 취약 테스트 앱은 반드시 격리 환경에서만 운영하며 외부 네트워크 노출을 금지한다(규칙 2: 스코프 격리). |
| **통제 — 7대 안전장치 회귀 필수** | 매 스프린트 7대 안전장치(승인 자산·스코프 격리·비파괴·DoS 금지·감사로그·데이터 최소수집·악용 산출물) 회귀는 통과 필수 항목이며 생략 불가하다. |
| **통제 — DoD 미충족 시 릴리스 차단** | DoD 기준 미달 상태에서는 릴리스 판정을 내릴 수 없으며, PM과 합의 없이 단독으로 릴리스를 승인하지 않는다. |
| **통제 — 측정 재현 가능성** | 모든 탐지율·오탐율 측정은 동일 조건에서 재현 가능해야 하며, 측정 환경·파라미터를 문서화한다. |

## 3. 주요 담당 업무

1. **탐지율·오탐율 측정** — 취약 테스트 앱(Juice Shop · DVWA · WebGoat) 대상으로 매 스프린트 Recall / FP Rate를 측정하고 추이를 기록한다.
2. **정상 사이트 오탐 케이스 교차검증** — 정상 사이트 스캔 결과를 교차 검토해 오탐 판정의 근거 데이터를 연구원에게 제공한다.
3. **안전장치 회귀 테스트** — 공통 통제 7대 규칙 준수 여부를 회귀 테스트로 매 스프린트 확인한다.
4. **S4 검증 보조 · S7 재검증** — 절차 S4(검증) 단계에서 연구원을 보조하고, S7(재검증) 단계에서 최종 확인 책임을 수행한다.
5. **DoD 게이트 점검** — 각 스프린트 종료 시 DoD 충족 여부를 점검하고, PM과 합의해 릴리스 가능 여부를 판정한다.

## 4. 핵심 필요 역량

- **보안 테스트 시나리오 설계** — OWASP Top10 · WSTG · CWE 기반의 취약점 테스트 케이스를 작성하고 커버리지를 관리하는 능력.
- **측정 기반 품질관리** — 탐지율(Recall) · 오탐율(FP Rate) · CVSS 등 정량 지표를 정의·측정·분석하고 개선 루프를 운영하는 능력.
- **회귀 자동화** — 안전장치 회귀 및 스캐너 품질 회귀를 자동화 파이프라인으로 구성하고 CI에 통합하는 능력.
- **격리 환경 운영** — 취약 테스트 앱 환경(Docker 등)을 격리 상태로 구성·유지하는 실무 경험.
- **협업 커뮤니케이션** — 측정 결과를 PM · 연구원 · 엔지니어가 공통으로 이해할 수 있는 형태로 보고하는 능력.

## 5. 오케스트레이션 내 위치

### (a) RACI 표 (S0~S7)

| 절차 | 내용 | QA/검증 |
|------|------|---------|
| S0 | 스코프 정의 | – |
| S1 | 자산 승인 | – |
| S2 | 스캔 계획 | I |
| S3 | 스캔 실행 | I |
| S4 | 검증 | R |
| S5 | 레포트 생성 | – |
| S6 | 조치 가이드 | I |
| S7 | 재검증 | R |

### (b) In / Out

| 방향 | 항목 |
|------|------|
| **Input (수신)** | 후보·확정 취약점 목록, 릴리스 후보 빌드 |
| **Output (산출)** | 탐지율·오탐율 측정 보고, 안전장치 회귀 결과, 릴리스 판정 의견 |

### (c) 결정권 · 에스컬레이션

- **릴리스 판정**: DoD 충족 여부를 QA가 확인하고 PM과 합의하에 "릴리스 가능" 판정을 내린다. QA 단독 결정이 아니며 PM 합의가 필수다.
- **오탐 최종 판정**: 오탐 여부의 최종 결정권은 연구원에게 있다. QA는 정상 사이트 교차검증 데이터를 근거로 제공한다.
- **에스컬레이션 기준**: 7대 안전장치 회귀 실패, DoD 미충족, 탐지율이 합의 임계값 이하로 하락하는 경우 즉시 PM · 연구원에게 에스컬레이션한다.

## 6. Phase별 업무

| Phase | 주요 QA 업무 |
|-------|-------------|
| **P1** | 안전장치 회귀 기준선 수립, 취약 테스트 앱(Juice Shop · DVWA · WebGoat) 격리 환경 구성 및 검증, DoD 초안 PM 합의 |
| **P2** | 탐지율·오탐율 측정 루프 가동(핵심), 매 스프린트 Recall / FP Rate 측정·추이 관리, 회귀 자동화 파이프라인 운영 |
| **P3** | 레포트 및 조치 가이드 정합성 검증(CVSS 점수·CWE 매핑·조치 내용 정확성), S7 재검증 |
| **P4** | 인증 영역 및 세션 관리 취약점 검증, 성능·속도제한 안전장치 회귀, 최종 릴리스 게이트 DoD 점검 및 PM 합의 |

## 7. 산출물 + DoD

| 산출물 | 설명 | DoD 기준 |
|--------|------|----------|
| **탐지율·오탐율 측정 보고서** | 스프린트별 Recall / FP Rate 수치 및 추이 | 재현 가능한 조건 문서화, 이전 스프린트 대비 Recall 유지 또는 향상 |
| **안전장치 회귀 결과** | 7대 안전장치 항목별 Pass/Fail 체크리스트 | 전 항목 Pass, 실패 시 즉시 에스컬레이션 기록 |
| **정상 사이트 오탐 교차검증 데이터** | 정상 사이트 스캔 결과 및 오탐 근거 | 연구원이 최종 판정에 활용 가능한 형태로 제공 |
| **릴리스 판정 의견** | DoD 체크리스트 + PM 합의 기록 | DoD 전 항목 충족 확인, PM 합의 서명(또는 동의 기록) 포함 |

## 8. 협업 인터페이스

| 협업 대상 | 인터페이스 내용 |
|-----------|----------------|
| **PM** | 매 스프린트 DoD 충족 여부 보고 및 릴리스 판정 합의; 탐지율 임계값·DoD 기준 사전 합의 |
| **연구원 (Researcher)** | S4 검증 보조: 후보 취약점 데이터 수신, 정상 사이트 교차검증 결과 제공; 오탐 최종 판정 근거 전달 |
| **엔지니어 (Engineer)** | 회귀 자동화 CI 연동 협의; 안전장치 미준수 항목 발견 시 즉시 피드백 |
| **공통** | 불변 감사로그(규칙 5)에 측정 기록·판정 이력을 남겨 추적 가능성을 보장한다 |
